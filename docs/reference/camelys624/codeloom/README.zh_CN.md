# Codeloom 审批器

Codeloom 审批器把 AI Passport 变成 Codeloom 工作区的随身伴侣：显示等待处理的智能体
权限请求和任务进度，并用三个按键批准或拒绝请求。设备通过 2.4 GHz Wi-Fi 直接访问
Codeloom 服务器（局域网 HTTP，也支持 HTTPS），配网完成后不需要手机应用或中转服务。
设备界面为简体中文。

分支：`feature/codeloom-approver`。状态：已实现并通过构建；尚未完成真机验收（见[验证](#验证)）。

## 前提

- Codeloom 服务器实现设备协议 v1：`POST /api/v1/devices`（网页端，生成配对码）、
  `POST /api/v1/devices/pair`、`GET /api/v1/device/overview`，以及使用设备令牌
  （`awd_…`）的 `POST /api/v1/approvals/:id/resolve`。
- 一个能访问该服务器地址的 2.4 GHz Wi-Fi。
- 一台带浏览器的手机或电脑，用于一次性配网。

## 配网步骤

1. 烧录固件。没有已保存配置时，设备开启名为 `Codeloom-XXXX`（MAC 末四位十六进制）
   的 WPA2 热点，并在屏幕上显示随机 8 位数字密码，每次开机重新生成。
2. 在 Codeloom 网页中添加设备，复制配对码（`pair_…`，10 分钟内有效）。
3. 手机连接该热点，打开 `http://192.168.4.1/`，填写 Wi-Fi 名称、Wi-Fi 密码、服务器地址
   （例如 `http://192.168.1.10:5181`）和配对码。
4. 设备关闭热点、连接你的 Wi-Fi，并以 `Passport-XXXX` 的名字调用
   `POST /api/v1/devices/pair`。两步都成功后，才把 Wi-Fi 凭据、服务器地址、设备令牌、
   设备 ID 和工作区名称写入 NVS（命名空间 `codeloom`，结构版本 1）并重启。
5. 失败时屏幕显示原因（Wi-Fi 密码错误、找不到网络、连接超时、服务器不可达、配对码
   无效或过期、服务器错误）；按 OK（或等待 60 秒）回到热点页面。网页会保留上次填写的
   SSID 和服务器地址；配对成功前不会保存任何内容。

需要重新配对时（例如设备在 Codeloom 中被吊销），在“状态”页选择“重置配置”。它会清除
`codeloom` NVS 命名空间和 Wi-Fi 驱动设置，然后重启进入配网模式。

## 页面与按键

| 页面 | 内容 |
| --- | --- |
| 审批（有待审批时的默认页） | 卡片显示类型（命令、写文件、工具、网络、其他）、标题、任务名和时间；提交中显示“发送中…”；有空状态和同步中状态；服务器待审批超过 8 条时给出提示。 |
| 审批详情 | 类型、时间，可滚动的标题与详情框，任务名，以及三个操作：批准、本次总是允许、拒绝。提交后任务行改为显示提交状态。 |
| 任务 | 汇总（总数、进行中、待审批）和最多 12 张任务卡片，包含状态标签和运行状态标签（等待审批以琥珀色突出）。 |
| 状态 | Wi-Fi 名称、IP、信号强度、服务器、工作区、设备 ID、固件版本、上次同步、空闲内存、最低空闲与最大连续块，以及带确认对话框的“重置配置”。 |

| 按键 | 列表 / 状态页 | 审批详情 | 重置确认 |
| --- | --- | --- | --- |
| 上 / 下 单击 | 移动选择或滚动（双击移动两步） | 移动操作焦点（默认“批准”） | 在“取消 / 重置”间切换 |
| OK 单击 | 打开选中的审批；在状态页打开重置确认 | 提交焦点所在的决定；出结果后关闭 | 确认当前选项 |
| OK 长按 | 回到审批页 | 返回列表 | 取消 |
| 上 长按 | 下一页：审批 → 任务 → 状态 → 审批 | 忽略（模态） | 忽略 |
| 下 长按 | — | 翻页查看详情文字 | — |

右上角显示电量，电量计读不到时隐藏。横幅依次显示“连接 Wi-Fi…”、“服务器不可达”
（连续两次轮询失败后）或“设备已吊销 · 请在状态页重置”。

## 行为

- **轮询：** 同步任务在屏幕点亮或变暗时每 5 秒、熄屏时每 20 秒请求一次
  `GET /api/v1/device/overview`，每次失败后间隔翻倍，最长 60 秒。收到 401 即标记为已吊销
  并每 60 秒重试，之后任一次成功会清除该状态。Wi-Fi 断线按 1 秒到 60 秒指数退避重连。
- **有界响应：** 响应超过 8192 + 512 字节时在接收过程中中止。交给 cJSON 之前先限制
  JSON 嵌套深度；数组最多取 8 条审批、12 个任务；字符串复制到定长缓冲并按 UTF-8 边界
  截断，控制字符折叠为空格；ID 只允许 `[A-Za-z0-9_-]` 后才会拼进 URL 路径。未知类型
  显示为“其他”，未知任务或运行状态显示为“未知”。
- **审批锁：** 提交中的审批不会被再次提交；提交成功（2xx，或 409/404 视为“已在别处
  处理”）的审批即使下一次 overview 仍然出现也不会再次提供；网络或服务器错误会释放锁，
  可以重试。选中或打开的审批从 overview 消失时，选择移到相邻项，详情页关闭并提示
  “该审批已在别处处理”，除非该审批的提交仍在进行。
- **提醒：** 本次开机后第一次见到的审批 ID（包括第一次同步时已存在的待审批）会点亮屏幕、
  播放一段合成的双音提示音，并跳到审批页选中该项；正在看详情或重置对话框时不跳转。
- **背光：** 30 秒无操作降到 15%，60 秒熄灭。屏幕变暗或熄灭时的第一次按键只用于唤醒。
- **机密：** Wi-Fi 密码、配对码和设备令牌不会写入日志，持有它们的请求缓冲用完即清零。
  热点密码每次开机随机生成，只显示在屏幕上。

## 架构

```text
按键回调 ──► 事件队列 ──► cl_app 任务 ── 状态机（codeloom_state.c）
                ▲               │  ├─ 持 bsp_lvgl_lock() 更新 LVGL 界面
                │               │  ├─ 背光策略（codeloom_timing.c）
cl_sync 任务 ───┘ ◄──── 命令 ───┘  └─ cl_audio 任务（提示音，首次响铃时才初始化 codec）
 （全部 HTTP，overview 交接）
cl_setup 任务（仅配网模式）：SoftAP + esp_http_server + STA 验证 + 配对
```

有主机测试的纯 C 模块：`codeloom_text`（UTF-8、JSON 转义、ISO-8601、相对时间）、
`codeloom_url`（服务器地址校验与规范化）、`codeloom_setup_form`（有界表单解码与校验）、
`codeloom_protocol`（有界 cJSON 解析与请求体）、`codeloom_settings`（配置校验与通过后端
虚表的版本化持久化）、`codeloom_state`（状态机）、`codeloom_timing`（背光、轮询、重连时序）
和 `codeloom_chime`（提示音合成）。基线的 `demo_*.c` 与 `ui_pixel*.c` 保留在仓库中作为参考
并继续接受主机测试，但不编进本固件。

## 字体与内存

- 字体是由 `tools/gen_codeloom_fonts.py` 生成的思源黑体（Noto Sans SC）子集（详见
  [资源目录说明](../../../../assets/README.zh_CN.md)）：16 px 覆盖 ASCII、常用标点、全部 3755 个
  GB2312 一级汉字和所有界面文字；14 px 与 22 px 覆盖 ASCII、标点和界面文字。
  `LV_SYMBOL_*` 图标由 Montserrat 提供。字体之外的动态字符（例如 emoji）替换为可见的
  U+25A1 方框。`tests/test_codeloom_fonts.py` 在主机上检查覆盖率，固件开机时再用
  `lv_font_get_glyph_dsc()` 检查一次。
- 静态内存（ESP-IDF `idf.py size`）：321 KB D/IRAM 中静态占用约 176 KB，剩余约 145 KB
  作为堆。主要占用是 32 KB LVGL 内存池、状态机中的定长 overview（约 12 KB）以及 8.7 KB
  响应缓冲。每次解析出的 overview 放在临时 12 KB 堆缓冲中，在 HTTP/TLS 资源释放后才分配，
  由应用任务用完释放。关闭了 Wi-Fi IRAM 优化并把静态接收缓冲减到 6 个，把内部 RAM 还给堆；
  mbedTLS 使用动态缓冲；蓝牙已关闭。
- 固件在开机、外设就绪、热点启动前后、手机接入、Wi-Fi 连通和第一次 HTTP 请求之后记录
  空闲堆、最低空闲堆和最大连续块，并每 60 秒记录一次堆和 LVGL 内存池占用；状态页显示实时堆数值。
- LVGL 内存池为 32 KB。用真实界面代码在 64 位主机上临时渲染，12 个任务的满页峰值约 34 KB
  （8 条审批约 29 KB）；ESP32-C3 为 32 位，指针类字段减半，设备上的数值应更低，但必须用周期日志确认。

## 验证

- `./tools/validate.sh` 运行仓库检查、全部主机测试（包括 Codeloom 解析器、状态机、配置、
  URL/表单、时序和字体覆盖测试）以及固件构建和合并镜像校验。
- 下列真机测试尚未执行。

### 真机验收清单

1. 把校验过的 `build/FoloToy-AI-Passport-full.bin` 烧录到空白或有意重置的设备，确认开机
   直接进入配网界面（没有基线测试菜单），记录开机堆日志。
2. 用 Android 和 iOS 连接 `Codeloom-XXXX`，打开 `http://192.168.4.1/` 确认页面显示正常。
   分别测试超大或格式错误的表单、错误的 Wi-Fi 密码、只有 5 GHz 或不存在的 SSID、不可达的
   服务器地址和过期配对码；每种情况都应显示对应原因并回到配网，且不保存任何内容。
3. 成功配对；确认重启后进入审批页或任务页，Codeloom 网页中设备状态为已激活并显示固件版本。
4. 在 Codeloom 中触发一个命令审批：屏幕点亮、响铃、出现卡片。打开详情，用“下”长按翻看
   长文本；在不同审批上分别测试三个决定，确认 Codeloom 记录为 allow、allow_always、deny，
   且该审批不再出现。
5. 详情页打开时在浏览器中处理同一审批（应显示“已在别处处理”），以及在提交过程中断开服务器。
6. 对照 Codeloom 检查任务页（包括等待审批的任务），对照路由器和服务器检查状态页数值。
7. 停止服务器（约 10 秒后显示“服务器不可达”）、关闭路由器（显示“连接 Wi-Fi…”并能自动
   重连）、在 Codeloom 中吊销设备（显示“设备已吊销”，提交被阻止）。
8. 放置不动：30 秒变暗、60 秒熄屏，第一次按键只唤醒，新审批会点亮屏幕。条件允许时测量
   各状态电流。
9. 配置使用公共可信证书的 `https://` 服务器地址，重复第 3–4 步，记录 TLS 握手后的最低堆。
10. 检查所有页面是否有缺字方框、圆角处裁切、长标题、任务名中的 emoji 以及电量显示。
11. 使用“重置配置”，确认设备回到配网模式且热点密码已更换。

## 已知限制

- 尚未在硬件上验证：显示效果、按键时序、音量、真实手机上的 Wi-Fi/SoftAP 行为、HTTPS 内存
  余量和续航。
- 没有弹窗认证 DNS 服务；需要手动打开 `http://192.168.4.1/`。配网网页是设备自身 WPA2 热点上
  的明文 HTTP。
- HTTPS 只使用 ESP-IDF 证书包，不支持自签名证书和证书固定。
- 只显示服务器返回的前 8 条待审批和前 12 个任务。
- 未启用自动 light sleep；省电依靠背光策略、Wi-Fi modem sleep 以及每次响铃后让 codec 休眠。
- GB2312 一级字表之外的动态文字（生僻字、emoji）显示为方框。
